# Tasks for Today Management System

Laravel implementation of IT0049 Technical Summative Assessment 3 by **Lexus Gabrielle Medina**, TC31 BSITCST. Professor: Doc Roman Villones.

A responsive, database-backed task dashboard with a today-only Welcome page, a complete Task List, a Profile page, and an About page. The task records and sample user are retained from the original TSA1 implementation.

## Submission links

- Repository: https://github.com/Lexxxx12/tasks-for-today-laravel-tsa3

## Requirements

PHP 8.4 or newer (the lockfile includes Symfony 8), Composer 2, and PHP extensions including PDO SQLite, mbstring, OpenSSL, ctype, fileinfo, tokenizer, DOM and XML. No Node build step is needed: Blade uses the stylesheet in `public/css/app.css`. Optional Google Fonts fall back to local fonts when offline.

## Local setup

```sh
git clone https://github.com/Lexxxx12/tasks-for-today-laravel-tsa3.git
cd tasks-for-today-laravel-tsa3
composer install
cp .env.example .env
php artisan key:generate
php -r "file_exists('database/database.sqlite') || touch('database/database.sqlite');"
php artisan migrate --seed
php artisan serve
```

Open http://127.0.0.1:8000. SQLite is the default. All dates and the meaning of “today” use `Asia/Manila` in `config/app.php`, independent of the web server timezone.

## Required pages

| Route | Behavior |
| --- | --- |
| `/` | Queries `Task::forToday()` and displays only records with today's `task_date` |
| `/tasks` | Retrieves every task, ordered by `task_date`, then ID |
| `/profile` | Retrieves the single seeded user with Eloquent |
| `/about` | Identifies the developer, course, section and professor |

The original TSA1 sample account is `sample`, **Sample**, `sample@example.com`. It is a demonstration profile, not an authentication account. Developer information appears on the About page. Task statuses are displayed as Pending, In progress and Completed. Task editing and registration are outside this assessment's four-page scope.

## Schema and seed data

- `tasks`: ID, title, status (default `pending`), indexed task_date, created_at, updated_at.
- `users`: ID, unique username, full_name, email, created_at, updated_at.
- `database/migrations` contains the complete versioned schema.
- `database/seeders/DatabaseSeeder.php` creates exactly **8 tasks across 3 dates**, including **4 today**, **2 yesterday**, **2 tomorrow**, and **exactly 1 user**. A SQL export is unnecessary because migrations and the seeder reproduce the database.

Dates are relative to the day of seeding. Records remain attached to their actual stored dates; the Welcome page correctly becomes empty on a day without tasks. To reset the demonstration for a new review date, run `php artisan db:seed` (replaces demo tasks and the user). This operation is transactional and repeatable. Do not run it against a database containing records you want to keep.

## Structure

- `app/Models/Task.php`: Eloquent model, date cast, today scope, status labels.
- `app/Models/User.php`: Eloquent user model.
- `app/Http/Controllers`: task retrieval and profile retrieval.
- `resources/views`: four Blade pages, a shared layout, and a shared task table.
- `public/css/app.css`: responsive layouts and status styling.
- `tests/Feature/TaskManagementTest.php`: database, routing, date filtering, ordering and escaping checks.

## Verification

```sh
php artisan test
php artisan route:list
php artisan view:cache
```

Tests use an in-memory SQLite database, a fixed Manila date and fixtures around midnight. They check that yesterday and tomorrow cannot leak into today's page, every task is included in date order, the profile and developer details render, HTML is escaped, the default status is pending, and usernames are unique. They also verify repeat seeding, exactly eight tasks, three distinct dates, one user and the empty state.

## Hosting on Render

The repository includes a `Dockerfile`, `docker/start.sh`, and `render.yaml`. Connect the repository to a free Docker web service or create a Render Blueprint from `render.yaml`. No credit card or paid service is required by the configuration. The Apache web root is `public/`, migrations run at startup, and the demonstration is seeded only when no tasks exist. Configure `APP_ENV=production`, `APP_DEBUG=false`, `LOG_CHANNEL=stderr`, and set `APP_URL` to the live HTTPS URL. A Laravel key is generated at startup if one is not supplied; for persistence, set `APP_KEY` to a key generated by `php artisan key:generate --show`.

The free Render filesystem is ephemeral. A redeploy or restart may reset the SQLite database and recreate demonstration records. This app has no login or editing flows, so that is suitable for this read-only laboratory demonstration. Use a persistent disk or managed database for durable production records. Free services can also sleep when idle; allow time for the first request to wake the service.
